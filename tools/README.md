# Beat Lab

独立的节拍检测测试页，不属于插件，不会被打进 npm 包。

```text
node tools/beat-lab-server.mjs
```

打开 `http://127.0.0.1:8899/`。

可以：

- 采集系统声音（Chrome/Edge 的分享窗口里勾选“分享音频”）。
- 采集麦克风。
- 载入本地音频文件，做一次分析。
- 生成 12 秒 120 BPM 的测试点击，校验 BPM 和节拍数。
- 调整分析窗口与自动分析间隔。
- 查看每次 `detect()` 的耗时、BPM、置信度、节拍数和与参考 BPM 的误差。

页面使用 `runtime/electron-helper/vendor/beat-detect.js`，与插件桌面模式是同一份
`@audio/beat` 检测代码；插件在 Worker 中运行，这个页面在主线程运行，因此页面上的
耗时是算法计算量参考，不包含插件 UI 的绘制时间。

## Whale Beat Live（真实插件监视器）

`beat-lab.html` 是独立采样器；`beat-live.html` 则直接读取正在运行的桌面挂件，
不采集音频，也不修改插件设置。

```text
node tools/beat-live-server.mjs
```

打开 `http://127.0.0.1:8898/`。先在 DSH 桌面模式中开启音乐律动。

工具通过 helper 写入系统临时目录的 `dsh-whale-bongo-bridge.json` 自动发现端口，
订阅 `http://127.0.0.1:<helper-port>/audio-beat/stream`，显示：

- 插件当前 BPM、置信度和候选 BPM（含确认次数）。
- 下一次拍点倒计时、节拍周期、提前量和网格年龄。
- 系统音频 RMS 能量、缓冲窗口、分析耗时和分析间隔。
- 实时能量曲线、已触发拍点、最近分析表和事件日志。

只读数据流：helper 不把工具的请求转发给音频采集器，工具本身也没有麦克风或
屏幕采集代码。

### 录制与导出

右上角「开始录制」后，工具会记录这段时间收到的**每一个遥测帧**（约 100ms 一帧），
同时单独记录：

- 拍点事件（时间、BPM、置信度、能量、候选 BPM）
- 每次 BPM 分析结果（含 `@audio/beat` 返回的拍点偏移和计算耗时）
- 状态变化、连接变化和工具事件日志
- helper 端口、采样率、分析间隔、环境信息

停止录制后点「导出录制」，会下载 `whale-beat-recording-<时间>.json`。
录制上限 15 分钟；建议固定 BPM 测试时录制 20–40 秒，并保持工具窗口不要刷新。

导出的 JSON 可直接上传，用来复现：

- 开头 BPM 误判/倍频/半频
- 拍点是否提前或滞后
- BPM 修正时是否多触发一次
- 分析耗时和节拍网格稳定性
